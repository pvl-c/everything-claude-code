# Berlin Venture Council

Консилиум из тринадцати экспертов для разбора бизнес-идей на немецком рынке. Задача — не вдохновить, а **сэкономить год жизни**: понять за один разбор, есть ли здесь бизнес, и если есть, какой первый шаг.

## When to Use

- Пользователь приносит тему или идею продукта для Германии, Берлина или DACH
- Нужен поиск ниш: «где сегодня копать»
- Нужна проверка: почему это сработает, почему нет, какая минимальная команда
- Нужно понять, вытянет ли это один человек с ИИ
- Нужна оценка окна: регуляторный дедлайн, тренд, конкурентная плотность

## When NOT to Use

| Вместо консилиума | Используй |
| --- | --- |
| Общая проверка решения без немецкой специфики | `council` |
| Готовая идея, нужен план реализации | `planner` |
| Нужны только конкурентные данные | `market-research` |
| Материалы для инвестора | `investor-materials` |
| Разбор технического решения | `architect` |

## How It Works

### 1. Формулировка

Модератор сводит тему к одному проверяемому вопросу и фиксирует рамку: покупатель, боль, текущее решение, критерий успеха. Если тема широкая — сужает сам и говорит, как именно.

### 2. Параллельный разбор

Эксперты запускаются **одним сообщением, параллельно**. Каждый получает одинаковый контекст и не видит ответов остальных — это защита от группового мышления. Обязательное ядро: инвестор, экономист, продукт, техника, GTM, финансы, скептик, фаундер. Остальные подключаются по релевантности (см. таблицу в `bvc-moderator`).

Каждый эксперт обязан вернуть числовую оценку по своей рубрике и назвать главный риск.

### 3. Поиск разлома

Модератор ищет противоречия между экспертами и называет их вслух. Совпадение всех мнений — повод отправить скептика на второй заход.

### 4. Вердикт

```
ВЕРДИКТ: GO / GO ПРИ УСЛОВИИ / NO-GO
Ставка одним предложением
Почему сработает — 3 причины с фактами
Почему не сработает — 3 механизма смерти
Минимальная команда
Что делает один человек с ИИ, а что нет
Первый шаг на 2 недели
Сигнал закрытия
```

## Рубрика оценки

Полная рубрика с весами и порогами: `references/scoring-rubric.md`.
Справочник по немецкому рынку — регуляторные окна, каналы, ценовые ориентиры: `references/german-market-context.md`.

## Правила консилиума

1. **Цифры вместо прилагательных.** Не «большой рынок», а «N предприятий × €X в год». Не «быстро», а «6 недель».
2. **Источник или пометка.** Любой внешний факт — со ссылкой; если проверить не удалось, пометь «требует проверки».
3. **Рынок считается снизу.** TAM из чужих отчётов не принимается.
4. **Боль измеряется в евро или часах.** Меньше двух часов в неделю — в Германии не покупают.
5. **Механизм важнее мнения.** «Не взлетит» без механизма смерти не засчитывается.
6. **NO-GO — нормальный результат.** Половина хороших идей не бизнес, и об этом говорят прямо.
7. **Немецкие термины в оригинале** с пояснением при первом упоминании.

## Examples

**Поиск ниш**

> Пользователь: найди 10 ниш для digital-продукта в Германии

Модератор запускает экономиста (регуляторные окна), Mittelstand-эксперта (боли), госсектор-эксперта (бюджеты), инвестора (что финансируют), GTM (что продаётся), скептика (что переполнено). Синтезирует список ниш, каждая — с окном, покупателем, ценой, конкурентами и оценкой по рубрике.

**Разбор конкретной идеи**

> Пользователь: хочу сделать ИИ-помощника для Handwerker, который сам заполняет отчёты

Полная панель. Mittelstand-эксперт проверяет реальность процесса, юрист — персданные сотрудников и Betriebsrat, техлид — стоимость инференса, CFO — цену против готовности платить, скептик — существующих игроков.

**Проверка окна**

> Пользователь: стоит ли делать что-то вокруг обязательной электронной отчётности

Экономист даёт даты и охват мандата, growth проверяет поисковый спрос, скептик проверяет, не покрыли ли это уже крупные вендоры, инвестор оценивает, венчур это или bootstrap.
